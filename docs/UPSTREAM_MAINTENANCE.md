# Keeping the Agenda Fork in Sync with Upstream

Agenda is a self-contained product under `app/products/agenda/`. Merging upstream releases
should only touch the small set of core files listed below.

## Files outside `app/products/agenda/`

| File | Change | Conflict risk |
|---|---|---|
| `app/client/rest/index.ts` | import `ClientAgenda`, add it to the `Client` interface and mixin list | Low: lists change rarely, re-add one entry |
| `app/constants/screens.ts` | import `AGENDA_SCREENS` and spread it into the screens object | Low |
| `app/screens/home/tab_bar/index.tsx` | Agenda icon in `TabComponents`; tabs filtered with `useAgendaEnabled`; highlight and `isFocused` use the index among visible tabs (`focusedIndex`) | Medium: upstream edits the tab bar when it redesigns navigation |
| `app/screens/home/tab_bar/index.tsx` (Slack-style restyle) | slider replaced by a tinted pill behind the selected icon, a localized label under every icon (`tab_bar.*` strings), `Pressable` instead of `TouchableOpacity` | Medium |
| `app/constants/view.ts` | `BOTTOM_TAB_HEIGHT` 52 -> 64 to fit the labels | Low |
| `app/constants/screens.ts` | `AGENDA_SCREENS.AGENDA` added to `HOME_TAB_SCREENS` (tab path resolution) | Low |
| `app/screens/home/channel_list/channel_list.tsx` | floating **New message** button (phones only) that opens Create Direct Message | Low |
| `app/components/floating_action_button/` | new shared floating button used by Home and Agenda | None (new files) |
| `app/routes/(authenticated)/(home)/_layout.tsx` | `Tabs.Screen` for `Screens.AGENDA` before Account | Low |
| `app/routes/(authenticated)/(home)/agenda.tsx`, `app/routes/(authenticated)/agenda_*.tsx` (5 files) | new route wrappers | None (new files) |
| `tsconfig.json`, `babel.config.js` | `@agenda` path alias | Low |
| `eslint.config.mjs` | `@agenda` in the import-order path group | Low |
| `assets/base/i18n/en.json` | `agenda.*` strings (generated by `npm run i18n-extract`) | Low: re-run the extractor after merging |
| `docs/AGENDA_*.md`, `docs/IOS_BUILD.md`, `docs/UPSTREAM_MAINTENANCE.md`, `docs/agenda_integration_results.md` | documentation | None |

Nothing else in core changed. Agenda adds no native code, no pods, no patches under
`patches/`, no database schema and no dependencies. It uses `moment-timezone`,
`@react-native-community/datetimepicker` and `react-intl`, which upstream already ships.

## Merge procedure

```bash
git fetch upstream
git checkout feature/agenda
git merge upstream/main          # or rebase
npm ci && npm run pod-install
npm run i18n-extract             # resolves en.json conflicts by regenerating
npm run check                    # lint + tsc
npx jest app/products/agenda app/screens/home/tab_bar
```

When resolving conflicts in `tab_bar/index.tsx`, keep using `focusedIndex` (not `state.index`)
for the highlight and `isFocused`. With the Agenda tab hidden, `state.index` counts the hidden
route and the wrong tab is highlighted. `tab_bar/index.test.tsx` catches this.

## Upstream APIs Agenda depends on

If upstream renames or changes any of these, update the Agenda code that uses it:

- `ClientBase.doFetch`, `ClientError.status_code`, `getPluginsManifests`
- `navigateToScreen`, `usePropsFromParams`, `useNavigationHeader`/`getHeaderOptions`
- `IntegrationSelector` with `SettingsStore.setIntegrationsSelectCallback` (team/channel pickers)
- `useTabs`/`Tabs`, `Loading`, `FormattedText`, `CompassIcon`, `channel_item` styles
- Queries: `queryMyTeams`, `queryTeamsById`, `queryMyChannelsByTeam`, `queryChannelsById`,
  `queryUsersById`, `observeCurrentTeamId`, `observeCurrentUserId`, `observeTeammateNameDisplay`
- `fetchMissingProfilesByIds`, `showPermalink`, `displayUsername`

## Following Agenda plugin changes

- The TypeScript types in `app/products/agenda/types.ts` mirror the plugin's Go models. When
  the plugin adds fields, add them only after the server sends them.
- `utils/calendar.ts` and `utils/recurrence.ts` are ports of the plugin webapp's
  `calendar_utils.ts`, `event_utils.ts` and `recurrence_utils.ts`. Diff those files when the
  plugin changes recurrence behavior and port the change. The tests in
  `utils/recurrence.test.ts` pin the current semantics.
- If the plugin adds a channel scope to `GET /events`, replace the client-side channel filter in
  `fetchAgendaEvents`.
- `AGENDA_PLUGIN_ID` is in `app/products/agenda/constants.ts`.

## Known gaps (candidates for later work)

- Assignee editing beyond "assign to me" on creation. The plugin's `/assignees` endpoint
  exists but is not wired up.
- Creating or editing recurrence rules, and editing or cancelling single occurrences
  (`occurrenceStartAt`). Mobile edits act on the whole series and say so in the form.
- Changing visibility or scope of existing records, reminders and calendar colors.
- Offline cache.
